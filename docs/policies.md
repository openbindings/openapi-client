# Client policy register

The OpenAPI specifications and the RFCs they rely on are the client's only
behavioral authority. This register records existing Rust choices where those
standards do not determine a unique client behavior or host representation.
It introduces no new behavior. Standard-mandated edition interpretation is
outside this register. Every entry cites current documentation and/or existing
implementation/tests. Unsupported profiles are limits, not complete-edition
conformance claims.

Configuration means an existing caller control, not a proposed switch. Some
choices are fixed; the API does not currently make every policy configurable.
A host declaration records capabilities and cannot make an unfaithful host
faithful. See [the API contract](public-api-v1.md) for the supported call flow.

| ID | Existing client choice | Caller configuration | Code-backed source |
| --- | --- | --- | --- |
| P01 | No implicit redirect following. Core admission requires a host that does not follow redirects; native HTTP and Fetch use manual redirects. Nonopaque 3xx responses remain evidence. | Fixed for admitted invocation; there is no redirect-follow switch. The caller can inspect a response and explicitly initiate another call. | [Host contract](../rust/client/HOSTS.md), [host restriction tests](../rust/client/tests/host_contract.rs) (`non_replay_restrictions_precede_replay_and_opt_in_never_relaxes_them`), [native redirect test](../rust/reqwest/tests/real_http.rs) (`redirects_are_evidence_and_never_followed`). |
| P02 | No ambient authentication. Credentials are explicitly supplied by scheme name and are scoped to permitted origins. Native automatic cookies/authentication and system proxies are disabled; Fetch omits ambient credentials. | Supply credential values and `Credential::origins` explicitly. Ambient authentication cannot be enabled through core admission or these companions. | [API guide](../rust/client/README.md), [native host profile](../rust/reqwest/README.md), [Fetch profile](../rust/fetch/README.md), [host admission tests](../rust/client/tests/host_contract.rs). |
| P03 | Core enters a supplied callback at most once and never retries. Default admission requires a no-replay declaration. Such a declaration permits proven-unsent recovery, but no repetition after serialization began or may have begun. | `ReplayPolicy::AllowHostManaged` explicitly admits a host without the no-replay declaration, preserving all other restrictions and recording host-managed assurance. It does not bound network attempts or enable a core retry loop. | [Host contract](../rust/client/HOSTS.md), [replay tests](../rust/client/tests/host_contract.rs), [native recovery profile](../rust/reqwest/README.md). |
| P04 | Automatic server election accepts exactly one usable effective server. Multiple usable servers produce `AmbiguousSelection`; authored order is not a tie-breaker. | Set `Selection::server` (or the request builder's server selector) and variable overrides. The automatic election rule is fixed. | [Selection and server implementation](../rust/client/src/prepare.rs) (`Selection`, `choose_server`), [selection recovery tests](../rust/client/tests/quality_repairs.rs) (`r09_corrective_input_selection_and_limits`). |
| P05 | Automatic request media election counts concrete declarations compatible with the supplied body. A unique compatible declaration is selected; ambiguous choices refuse. A media range requires a concrete choice. | Set `Selection::media` or the builder's media selection. Selected media still must match the declaration and body representation. | [Preparation policy tests](../rust/client/tests/preparation_policy.rs) (`automatic_media_election_counts_body_compatible_choices`, `explicit_media_selection_keeps_range_and_body_compatibility_rules`). |
| P06 | Multiple authored security alternatives require an explicit election, including an anonymous alternative. Supplied credentials never elect an OR branch. | Set `Selection::security` and provide every credential required by the selected alternative. The no-credential-election rule is fixed. | [Preparation policy tests](../rust/client/tests/preparation_policy.rs) (`security_alternatives_require_an_election_independent_of_credentials`). |
| P07 | Duplicate decoded object/mapping keys refuse. JSON syntax fallback to YAML cannot bypass duplicate-name refusal. Caller-serialized duplicate keys use the same exact-parser refusal. | Fixed; no first-key/last-key-wins mode. | [Loading profile](../rust/client/LOADING.md), [exact parser](../rust/client/src/value.rs) (`ExactJson::parse`), [YAML duplicate branch](../rust/client/src/yaml.rs), [Serde duplicate test](../rust/client/tests/serializable.rs) (`duplicates_use_existing_exact_parser_with_complete_constructed_source`). |
| P08 | URI reference resolution applies RFC 3986 literal-dot removal without general normalization. Completed operation path segments equal to `.` or `..` refuse, including segments composed from template and input bytes. Encoded dots remain distinct and are preserved by the core. | Literal completed-segment refusal is fixed. `HostCapabilities::encoded_dot_segments` declares whether a supplied host preserves encoded segments. Native HTTP refuses any target its URL parser changes, including normalized encoded dots; this has no opt-out. | [URI implementation](../rust/client/src/uri.rs), [dot-segment tests](../rust/client/tests/preparation_policy.rs) (`complete_literal_dot_segments_refuse_including_composed_values`, `empty_embedded_and_encoded_segments_keep_their_exact_targets`), [native profile](../rust/reqwest/README.md). |
| P09 | JSON number tokens remain exact; YAML numeric normalization preserves mathematical value without binary floating-point conversion. Numeric conveniences are checked. Typed Serde projection follows the caller's target numeric type, which may round or refuse. | Exact retention is fixed. Callers choose exact values, checked numeric conversion or ordinary typed projection and can configure conversion-work limits. No implicit lossy-conversion switch exists. | [Loading profile](../rust/client/LOADING.md), [numeric conversion tests](../rust/client/tests/quality_repairs.rs) (`r08_numeric_reasons_and_exact_policy`), [Serde numeric tests](../rust/client/tests/serializable.rs) (`numbers_keep_exact_integer_and_finite_float_representation`), [native typed example](../rust/reqwest/README.md). |
| P10 | Loading uses the documented finite YAML 1.2 Core-schema profile: one document, string mapping keys, JSON-compatible standard tags and acyclic bounded aliases. Unpaired JSON surrogate escapes refuse. YAML 1.1 boolean spellings remain strings; merge tags are unsupported. | Profile and Unicode refusal are fixed. Configure source/normalized-byte, node, depth, alias-step and number-conversion limits. | [Loading profile](../rust/client/LOADING.md), [YAML tests](../rust/client/tests/yaml_loading.rs), [YAML adapter](../rust/client/src/yaml.rs), [JSON parser contract](../rust/client/src/value.rs). |
| P11 | Style-based URI spaces use `%20`; content query parameters and URL forms use `+`. Tuple encoding and style encoding retain their documented distinct spellings. Reserved expansion is component-safe and never recursively decodes percent triples. | Fixed spelling/profile; authored style and applicable `allowReserved` choose the supported OpenAPI mode, not an arbitrary escaper. | [Serialization profile](../rust/client/SERIALIZATION.md), [shared serialization tests](../rust/client/tests/shared_serialization.rs), [serializer](../rust/client/src/style.rs). |
| P12 | Ambiguous style delimiters refuse rather than inferring a service convention: brackets in deepObject names, raw dots in exploded labels and active space/pipe delimiters in collection members/keys. | Fixed; no custom-delimiter inference or override. Choose a supported declaration/value representation. | [Serialization profile](../rust/client/SERIALIZATION.md), [boundary tests](../rust/client/tests/serialization_s2a_boundaries.rs), [serializer](../rust/client/src/style.rs). |
| P13 | Empty style-based parameter collections refuse; empty form collections emit nothing. Empty scalars remain supported subject to completed path-segment checks. | Fixed in the supported serializer; no empty-collection convention switch. | [Serialization profile](../rust/client/SERIALIZATION.md), [boundary test](../rust/client/tests/serialization_s2a_boundaries.rs) (`empty_collections_and_completed_dot_segments_keep_existing_policy`). |
| P14 | Work and retained data have explicit finite admission bounds. Source bytes and normalized YAML bytes are independently limited. Retained response bodies and headers have independent admission facts; host/parser allocation is outside these retained-byte promises. | Set `Limits` and `GraphLimits` for their documented scopes. Adapters consume the immutable `response_admission()` view; they cannot turn it into a host-memory bound. | [Loading bounds](../rust/client/LOADING.md), [graph bounds](../rust/client/GRAPH.md), [host admission contract](../rust/client/HOSTS.md), [limits implementation](../rust/client/src/value.rs), [response admission tests](../rust/client/tests/response_admission.rs). |
| P15 | Invocation preserves native evidence without imposing application success. Optional JSON policies use explicit refusal priority and retain decoded data/errors. Metadata cutoff alone leaves raw evidence usable but prevents JSON interpretation with `IncompleteHeaders`. | Choose `complete_2xx_json` for known complete upload, `received_2xx_json` to accept upload uncertainty, or inspect `Outcome` directly. Response evidence and decode completeness rules are fixed. | [Policy implementation](../rust/client/src/policies.rs), [policy tests](../rust/client/tests/quality_repairs.rs), [host metadata contract](../rust/client/HOSTS.md), [admission tests](../rust/client/tests/response_admission.rs). |
| P16 | Loading and reference inspection use supplied bytes only. Missing resources produce corrective needs; loading never authorizes file/network retrieval or reuses invocation credentials. Preparation performs no schema evaluation or default insertion. | Supply resources and retrieval identities through `DocumentBuilder`, then build a new snapshot. Acquisition and any application validation/default policy remain caller-owned; there is no implicit-acquisition/default switch. | [Loading profile](../rust/client/LOADING.md), [resource graph](../rust/client/GRAPH.md), [graph tests](../rust/client/tests/resource_graph.rs), [API guide](../rust/client/README.md). |

The optional companions impose additional documented host restrictions. Native
HTTP timeout and trust-root configuration is in the
[native guide](../rust/reqwest/README.md); Browser/Worker representation and
replay limits are in the [Fetch guide](../rust/fetch/README.md). A configurable
deadline or admission bound does not waive a fidelity restriction.
