# Capability and policy matrix

This is the repository's single capability/policy matrix for the finite Rust
profile. OpenAPI and the RFCs it cites establish normative semantics; local tests
establish implementation, never authority. The [policy register](../../docs/policies.md)
uses IDs P01–P16 and CP17–CP24 for client policies. Host and constructor choices
are policies even when a row also cites a normative standard.

Revision: main `7de316b1ec5d970284cf244ec38eb56b565019d8` with the uncommitted
call-surface documentation and example changes. Verification below is limited to the named local
gate and feature graph. Edition admission and a finite passing case do not prove
complete coverage. All rows inherit finite Limits and cooperative cancellation;
caller code, host buffering and remote effects lie outside those bounds.

Last checked: 2026-10-14. Core tests means the offline core suite with qualification enabled, excluding
`actual_loopback_wire_uses_one_consumer_for_all_editions_and_new_methods`, whose
socket bind is denied by this sandbox. The full verifier attempts that gate.
The existing ignored provider-preparation case remains ignored. Compile scope
alone does not qualify native sockets or Browser/Worker runtime behavior. No
streaming, WebSocket connection, schema evaluator, acquisition driver or OAuth
token acquisition is implemented. Normative links use the applied minor-family
clarifications, preserving authored patch spellings; no network verification was
performed for this documentation slice.
