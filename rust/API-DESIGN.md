# Public caller and ownership sketch

The first representation candidate is a flat source index with owned immutable bytes behind `Arc`, using serde_json RawValue for grammar validation and borrowed child spans. The adapter retains decoded member names, original ordering, source ranges and exact numbers. It rejects duplicate decoded names with both member ranges. Iterative construction and destruction avoid recursive owned trees. A depth precheck protects the reusable parser before grammar validation. This is an ingestion/index adapter, not a new general JSON parser.

`Document` owns an immutable exact JSON document and an operation index. `Operation` and `Value` retain their owner independently of the temporary caller buffer or document variable. Values expose original tokens, decoded strings, ordered members, checked numeric conveniences and source locations. Schema inspection returns authored values and context only. A failed parse retains original bytes and a safe located diagnostic, including the explicit lone-surrogate limitation.

Operations are selected by path/method, stable owned handle or unique operation ID. Lazy compiled operation state is independent of per-call selections/values/credentials; its owner-bounded cache never retains per-call secrets. Preparation yields immutable method, target, ordered headers and owned finite bytes. Server/media/security elections are explicit when ambiguous.

`PreparedRequest::invoke` takes a cancellation token, host capability declaration and a callback returning a future. The callback need not be Send; native Send futures are possible when its captures are Send. It receives owned finite dispatch data. Outcomes keep dispatch, upload, response, delivered bytes/provenance, cancellation and failures distinct. Core performs preflight, credential and final request checks; arbitrary callback allocations and remote effects remain host responsibilities.

The URI family is fluent-uri for grammar/components plus a narrow RFC3986 §5.2 resolver that removes literal dot segments only. No WHATWG normalization occurs in the core. Browser qualification glue explicitly refuses targets its URL stack would rewrite. The initial choice is tested before considering a second family.

Fixed resource defaults are in `qualification/fixtures/limits.json`. Per-instance limits may reduce the profile's resource ceilings; the engine will not accept a larger recursion ceiling without separate qualification. Limits produce errors, never truncated successful documents. Request payloads are finite; delivered response truncation retains metadata and partial bytes explicitly.

Client policies to qualify: reject null/empty-container/nested parameter values; preserve exact numeric spellings in serialization; percent-encode non-unreserved URI data; serialize cookie pairs with `; `; do not percent-encode headers; reject leading/trailing header whitespace and controls; use explicit UTF-8 Basic credentials with forbidden colon/control validation. SDK diagnostics display stable codes and source byte locations, never raw credentials or arbitrary callback text.

Public examples will compile these flows from a fresh local package: document-driven inspection/selection/preparation/invocation; operation handle after document drop; source/schema inspection; native Send and host-local Rc callbacks. The browser/workerd bridge remains qualification glue and owns disposable handles to this same engine.

The qualified layout reserves the exact node/queue capacity after serde_json has validated the complete grammar. A small structural counting pass skips quoted strings and excludes object member names; it does not interpret values or accept grammar. This avoids repeated large vector reallocations. Qualification found that macOS retained those freed allocation blocks despite zero live-byte growth: a 100-cycle stress process peaked around 716 MiB before reservation and 68 MiB in the first corrected measurement. The final report carries repeated timing evidence and the parsing-time tradeoff; the backing-owner representation and public semantics are unchanged.
